# Omnistash

Загрузка, синхронизация и организация YouTube-архивов в одном окне:
добавьте автора или ссылку — Omnistash докачает недостающее, свежее
принесёт сам, а библиотеку разложит по папкам и метаданным, вручную
разобрав копии. Работает на Windows, **без аккаунтов, телеметрии и
лишних настроек**.

## Идея проекта

Вокруг YouTube накопилось много разовых загрузчиков: каждый качает свой
плейлист или канал, кладёт файлы, куда попало, и на этом всё
заканчивается. **Omnistash — не очередной загрузчик, а дом для
собранной библиотеки.** Сегодня работает YouTube; другие площадки
подключатся потом (этап M16). Три равные задачи:

1. **Загрузить** — всё новое и всё пропущенное с любого подключённого
   источника.
2. **Синхронизировать** — держать локальную копию в согласии с источником:
   без дублей, с возобновлением после обрыва и пониманием того, какое
   хранилище отвалилось.
3. **Организовать** — превратить свалку файлов в каталог: метаданные рядом
   с файлом, разметка (теги, рейтинг, заметки), дедупликация с разбором
   копий и переездов, переупаковка по шаблонам, ручная привязка
   неопознанного. Отдельные коллекции-папки — этап M17.

Всё живёт в одном окне; расписание (авто-синк по часам) уже работает —
настраивается в разделе «Расписание».

## Возможности

### Источники

- **Сейчас — YouTube** — плейлист и канал (`@handle` либо
  `/channel/UC…`): снимок чанками с прогрессом, честный diff, выбор
  режима на каждую единицу.
- **Адаптеры других площадок** — следующий этап: подключение новой
  площадки описывается конфигом, а не правкой кода; схема к нему
  готова (ключ записи `platform:<id>`, каналы и плейлисты одинаковы).
  Одиночное видео и вход по cookie/токену — вместе с адаптерами.

### Загрузка

- **Очередь в базе** — строки переживают рестарт окна, падение одной не
  останавливает остальные; у каждой виден результат, а если строка
  упала — ещё и причина прямо в списке.
- **Возобновление** — `.part` докачивается с места обрыва, а очередь
  продолжается при старте окна (настройка «Продолжать очередь при
  запуске»).
- **Повторы** — ретраи с паузой и лимитом («Повторов при сбое»,
  «Пауза между запросами»), отдельно — «Повторить упавшие» одним
  нажатием.
- **ffmpeg по кнопке** — проект его не содержит (GPL), но ставит
  одной кнопкой с вашего согласия (см. «Поставить ffmpeg»); без него
  качаются готовые потоки, со склейкой и субтитрами в файл — после
  установки.
- **Перекодировка в HEVC** — настройка «Загрузка → Перекодировка»:
  `video.mp4` → `video [HEVC].mp4`, оригинал удаляется только после
  успеха; недоступные в вашей сборке кодеки (NVENC без NVIDIA и т. п.)
  гасятся в списке с пометкой, а не пропускаются молча.

### Синхронизация

- **Инкремент** — переснимается снапшот источника, считается diff и
  применяется: новые строки появляются в индексе, выпавшие помечаются
  убывшими, файлы не трогаются.
- **Контроль целостности** — sha256 каждого файла лежит в индексе: по
  нему находятся копии при переносе, а кнопка *«Целостность»* сверяет
  содержимое диска с индексом и перекачивает битые (см. «Разметить и
  проверить»).
- **Расписание** — два независимых таймера: автоскан и автосинк, каждый
  с интервалом в минутах (0 — выключено). Живут, пока открыто окно;
  в строке видно, когда следующий запуск и когда был последний. Для
  работы без окна — `omnistash.py --sync` под планировщик Windows.
- **Удалённое хранилище (FTP/FTPS)** — этап M14, отложен.

### Организация (библиотека)

- **Шаблон имени и пути** — куда и как ложатся **новые** загрузки:
  `%(channel)s/%(upload_date)s - %(title)s [%(id)s].%(ext)s` — синтаксис
  yt-dlp, `[%(id)s]` обязателен: по ID файлы узнаются в индексе.
  Переименование уже собранного — кнопка «Переупаковка» (см. ниже).
- **Метаданные рядом с файлом** — `post.json` (автор, дата, описание,
  ссылка на оригинал, обложка) и сама обложка лежат рядом с содержимым:
  библиотека самодостаточна и переиндексируется без сети.
- **Дедупликация** — копия, переезд и «возможный переезд» различаются по
  хешу, разбираются вручную в разделе «Дубликаты»; есть и ручная привязка
  файла к видео.
- **Разметка** — теги, рейтинг (0–5), заметка и «просмотрено»: в
  карточке или сразу для группы выделенных строк («Пометить…»). Теги
  индексируются поиском — наберите слово в строке поиска и найдите всё
  размеченное. Обложка показывается в карточке **из локального файла**
  (data-URI), то есть без единого сетевого запроса.
- **Теги, коллекции** — колонки и полнотекстовый поиск уже есть; отдельные
  «коллекции-папки» - этап M16.
- **Переупаковка** — кнопка *«Переупаковать…»* над таблицей: область
  (выделение или текущий фильтр слева) приводится к шаблону из
  настроек. Превью показывает, что станет, до нажатия: сколько
  переименований, конфликтов имён и файлов без метаданных — последние
  остаются как есть с причиной, а не получают `NA` в имени. Сайдкар,
  субтитры и обложка меняют имя вместе с видео, пустые папки убираются,
  корень хранилища не трогается, отмена безопасна.

### Интерфейс

- **Четыре вкладки**: Библиотека · Синхронизация · Очередь · Настройки —
  состояние видно в одном окне, журнал запусков живёт в «Синхронизации».
- **Два вида библиотеки** — список или плитка с обложками (кнопки ☰/▦
  в тулбаре, три размера плитки). Превью берутся только из локальных
  файлов и только когда попадают на экран; видео без обложки получает
  честную заглушку «нет обложки». Вид и размер сохраняются.
- **Видео открывается сразу** — двойной клик по строке или плитке
  (или кнопка «Открыть» в карточке) запускает системный плеер по
  умолчанию, «Открыть папку» открывает проводник с выделенным файлом.
  Одиночный клик по-прежнему открывает карточку.
- **Цветные статусы** — каждая строка очереди и каждый источник
  подсвечивают, что происходит прямо сейчас.
- **Внешний вид** — тёмная и светлая тема; свои темы, свой шрифт
  интерфейса и вторые языки — этап M15.
- **Всё локально** — настройки, журнал и индекс лежат в
  `%LOCALAPPDATA%\Omnistash`, ничего не отправляется наружу.

## Как это работает

```
источник ──▶ индекс ──▶ очередь ──▶ хранилище ──▶ сверка
 (снапшот)   (метаданные   (режим и    (файл +       (копия /
              и дерево)     выбор       post.json,     переезд /
                           вручную)    .part)         «возможный»)
```

1. **Источник** отдаёт снапшот: что есть у автора или в плейлисте.
2. **Индекс** пишет метаданные, авторов и связи — ещё ничего не скачивая.
3. **Очередь** качает по одному в **выбранное вручную хранилище**: файл
   лежит сразу в своей папке (до конца — как `.part`), рядом появляется
   `post.json` с полными метаданными и хешем.
4. **Сверка** после скана различает три случая: настоящая копия,
   настоящий переезд и «возможный переезд» (старое хранилище недоступно)
   — последний разбирается человеком.
5. **Синхронизация** переснимает источники и применяет diff: новые строки
   появляются, выпавшие помечаются, файлы не трогаются.

Прервать можно на любом шаге — следующий запуск продолжит с того же
места.

## Установка

```powershell
git clone https://github.com/vilminessa/Omnistash.git
cd Omnistash
pip install -r requirements.txt
python omnistash.py             # окно
python omnistash.py --scan      # переиндексация без окна (для watchdog)
```

### Сборка exe и CI

```powershell
python -m PyInstaller Omnistash.spec --distpath . --workpath build --noconfirm
# получится один Omnistash.exe (~28 МБ): ui_src вшит внутрь, профиль
# (настройки и индекс) остаётся в %LOCALAPPDATA%\Omnistash, версию exe
# берёт из version.py
```

Конвейер — на GitHub Actions, как в Synfronia:

- **ci** — на каждый push/PR: офлайн-тесты, синтаксис Python/JS, линт
  workflow-файлов (`tools/check_workflows.py`: пины SHA и permissions),
  сборка превью;
- **release** — по тегу `v*` или вручную (*workflow_dispatch*): проверки →
  `Omnistash.exe` → ассет релиза → SLSA-провенанс и `gh attestation
  verify`. Версия в `version.py` должна совпасть с тегом, иначе сборка
  падает на шаге сверки.

Живые тесты в CI не гоняются — там реальная загрузка с YouTube, а CI
должен быть детерминированным.

### Разработка: debug.bat

`debug.bat` — консоль управления проектом. Запуск без аргументов открывает
меню, с номером пункта — сразу выполняет его (удобно для скриптов):

```powershell
debug.bat            # меню (Enter показывает список)
debug.bat 4          # тесты офлайн
debug.bat 5          # тесты + живые на YouTube
debug.bat 6          # проверка синтаксиса python и node
debug.bat 7          # собрать preview.html и открыть в браузере
debug.bat 9          # git статус и последние коммиты
debug.bat A          # git add + commit + push (спросит сообщение)
debug.bat B          # убить процессы Omnistash
debug.bat C          # копия базы библиотеки в %LOCALAPPDATA%\Omnistash\backup
debug.bat D          # открыть папку профиля
debug.bat E          # синхронизация без окна (--sync)
```

**Превью интерфейса** (`tools/build_preview.py` → `preview.html`, в git не
идёт) — та же страница окна, но с вымышленными данными: мост pywebview не
подключён, и app.js сам подставляет мок-бэкенд. Так интерфейс можно
смотреть и править без запущенного Python; `--first` показывает стартовый
диалог первого запуска, `?empty=1` — и вручную.

## Как пользоваться

### Добавить источник

Кнопка **«Добавить»** в шапке → вставьте ссылку на плейлист или на канал
(`@handle` либо `/channel/UC…`) → выберите режим синхронизации →
*Индексировать*. Программа снимет снапшот (в базу пока ничего не пишется)
и покажет диалог: сколько метаданных будет добавлено — новых видео,
уже известных, авторов, связей, пропущенных и повторных записей.

*Добавить* запускает поэтапное создание — **Плейлист → Авторы → Видео →
Связи**, у каждой стадии свой счётчик. Всё идёт одной транзакцией:
падение или «Отмена» откатывают всё до последней строки, а повторный
запуск безопасен — существующее опознаётся и не дублируется.

Что происходит после, зависит от режима:

| Режим | Итог |
|---|---|
| **Полная** | новое сразу встаёт в очередь загрузки |
| **Частичная** | пикер: отмечаете, что качать прямо сейчас |
| **Ручная** | только счётчики, дальше всё по кнопке |

### Переиндексировать уже скачанные файлы

Настройки → **«Библиотека»** → *+ Добавить папку* (хранилищ может быть
несколько: локальный диск, внешний, сетевой) → кнопка **«Переиндексировать»**.
Файлы опознаются по `post.json`, по ID в имени, по названию и по хешу;
неопознанные попадают в библиотеку как локальные записи.

**Хранилища** — это первое, что спрашивает программа на старте (диалог
«Где хранить видео?»). Каждое знает своё состояние:

| Состояние | Что это | Что делает синк |
|---|---|---|
| доступно | папка на месте | обычный режим |
| **нет носителя** | диск отключён | не трогает файлы (это не «пропало») |
| **отключено** | вы выключили сканирование | не сканирует, строки целы |
| **отвязано** | папку забыли | пути забыты, видео помечены «откреплено» |

Отвязка спрашивает каждый раз, оставить ли след папки: со следом повторное
добавление узнаёт папку и предложит вернуть её, а скан восстановит файлы
по сайдкарам и ID — **без перекачки**. У каждой папки можно указать новый
путь (диск переименовали) — это перепривязка за транзакцию, без чтения
содержимого.

### Куда качать

Выбор хранилища — **всегда ручной**: фон ничего не решает за вас.

- **При добавлении источника** диалог спрашивает «Куда качать» — на экране
  ссылки и ещё раз при подтверждении. Выбор запоминается **у источника**
  и виден в колонке «Куда» списка «Источники»: именно туда поедут режим
  «Полная» и будущие синхронизации, без новых вопросов.
- Разово: выделите строки в библиотеке → в панели «Хранилище: …» →
  *Скачать*. То же — в карточке видео, в пикере «Частичной» и в итоге
  синхронизации.
- Цель записывается в строку очереди, а если носитель отключился — строка
  падает с внятной причиной («нет хранилища: Внешний 4ТБ не подключён»)
  и ждёт «Повторить упавшие». У источников, добавленных раньше, колонка
  «Куда» честно показывает «по умолчанию» — это глобальная настройка.

### Разметить и проверить

- **Карточка видео** (клик по строке): обложка из локального файла,
  звёзды рейтинга, теги через запятую, заметка, отметка «просмотрено» —
  *«Сохранить пометки»*. Повторный клик по звезде снимает оценку.
- **Группой**: отметьте строки чекбоксами → *«Пометить…»* → те же поля
  для всех выбранных. Пустые поля не меняются.
- **Найти размеченное**: теги участвуют в поиске — наберите слово в
  строке поиска; рейтинг фильтруется селектом рядом со статусом.
- **Проверить целостность**: кнопка *«Целостность»* сверяет файлы с
  хешем из индекса. Битые показываются списком, кнопка
  *«Перекачать битые (N)»* ставит их в очередь с перезаписью.

### Поставить ffmpeg и перекодировать

Проект ffmpeg не содержит и не распространяет — он под GPL, а Omnistash
под PolyForm Noncommercial. Зато он ставится одной кнопкой и только по
согласию:

1. Настройки → «Загрузка» → строка **FFmpeg** → *«Скачать ffmpeg»* (или
   кнопка в заметке вкладки «Очередь», если очередь уже раз качнулась
   без него). В диалоге сказано, что именно качается: сборка gyan.dev
   (при недоступности — зеркало BtbN на GitHub), ~100 МБ, встанет в
   `%LOCALAPPDATA%\Omnistash\bin`; удаляется удалением этой папки.
2. Установка атомарная: архив распаковывается в буфер, бинарник
   пробуется запустить (`ffmpeg -version`), и только после успешной
   пробы подменяет файл. Не скачался/не запустился — на месте остаётся
   прежняя версия или пустота, битого exe не бывает.
3. Что даёт ffmpeg: склейка видео+аудио, метаданные и субтитры
   **внутрь файла**, обложка, перекодировка. Без него всё тоже
   качается — просто готовыми потоками.

**Перекодировка в HEVC** — настройка «Загрузка → Перекодировка»:
`video.mp4` → `video [HEVC].mp4` (кодек hvc1, CRF 23), оригинал
удаляется только после успеха, обложка и сайдкар переименовываются
следом за видео. Какие кодировщики реально есть в вашей сборке,
спрашивается у самого ffmpeg: недоступные (например NVENC без
NVIDIA) гасятся в списке с пометкой, а выбранный GPU-кодировщик при
неудаче откатывается на программный x265.

### Аккаунт Google

Площадка иногда просит вход: возрастной контент и «подтвердите, что вы не
бот». Аккаунты живут в настройках (секция **«Аккаунт Google»**) и
**привязываются к конкретному источнику**: куки учётки уходят в синк этого
источника и в загрузку его видео. Несколько аккаунтов — каждый со своей
привязкой; глобального «аккаунта для всего» нет.

Как добавить аккаунт:

1. **Вход в окне приложения** — кнопка «Войти в окне…»: открывается окно
   на странице входа YouTube. Когда площадка выдаст сессию, **куки
   снимаются сами**, окно закрывается, аккаунт появляется в списке. Копия
   хранится **зашифрованной** (DPAPI — привязка к вашей учётке Windows:
   на другой машине или для другого пользователя файл бесполезен).
   Если авто-поимка не сработала — в том же диалоге кнопка
   **«Я вошёл — забрать куки»** снимает их вручную и объясняет, что видела
   («увидено кук N, аккаунтских M» — без значений).
2. **Куки из браузера** — настройка «Куки из браузера»: yt-dlp читает их
   напрямую, копий не создаётся. **Firefox работает**; Chrome/Edge v127+
   шифруют куки (App-Bound Encryption) — прочитать их сторонним инструментам
   нельзя, для них остаётся импорт.
3. **Импорт cookies.txt** — если Google откажет во входе из окна
   («This browser might not be secure»): экспортируйте куки расширением
   и импортируйте файл. Для экспорта из свежих Chrome/Edge используйте
   Firefox (см. выше).

Привязка: при добавлении источника выберите аккаунт в диалоге (на обоих
экранах) — выбор запоминается у источника и виден в списке «Источники».

Если поимка не работает — кнопка **«Проверить, что видит программа»**
в диалоге входа покажет, сколько кук видит окно и есть ли среди них
аккаунтские (без значений — только счётчики и домены); та же диагностика
пишется в журнал раз в30 секунд.

Честные оговорки:

- Сессия — это доступ к вашему аккаунту: копии живут только на этом
  компьютере (`accounts/<id>.bin`, зашифрованы DPAPI), никуда не
  отправляются; кнопка «забыть» удаляет аккаунт целиком. Ни в журнале,
  ни в настройках значений кук нет и быть не может.
- Вход в неофициальном клиенте может не понравиться площадке — это ваш
  выбор и ваш риск; куки протухают (обычно ~2 недели), при перестановках
  просто войдите заново.
- Куки помогают **загрузке и метаданным**. Отдельный OAuth для API —
  следующий подэтап.

### Переупаковка под текущий шаблон

Настройки → **«Загрузка»** → *Шаблон имени и пути* задаёт, как должны
лежать файлы. Кнопка **«Переупаковать…»** над таблицей библиотеки
приводит к нему выбранные строки (или всю текущую область, если ничего
не отмечено): сначала превью «что станет», потом переименование с
отменой.

Это переименование **внутри того же хранилища**; чтобы уехать на другой
диск — кнопка «Перенести…» в панели выделения (копия с проверкой
контрольной суммы).

### Первая синхронизация

Вкладка **«Синхронизация»** → *Синхронизировать всё*: каждый источник
переснимается, считается diff и применяется. Прогресс идёт по источникам
и стадиям (Плейлист → Авторы → Видео → Связи), внизу — итоговая таблица:
сколько новых, сколько уже было, сколько выпало и сколько встало в
очередь. Остановить можно в любой момент: незаконченный источник не
запишет ничего наполовину.

Если источники в режиме **«Частичная»** или **«Ручная»**, новые видео
попадают в индекс, но не качаются — кнопка *«Поставить в очередь (N)»*
рядом с итогом и есть ручной выбор. В режиме **«Полная»** они уходят в
очередь сами и качалка стартует сразу.

### Настроить организацию

Настройки → **«Библиотека»**: хранилища, режим синхронизации по
умолчанию, шаблон имени и пути, sidecar `post.json`, хеширование при
скане, возобновление очереди при старте.

### Выгрузить на хранилище (этап M14)

Настройки → **«Хранилище»**: выгрузка на FTP/FTPS-сервер (NAS и
подобные), шаблоны вида `media/{author}`, проверка подключения.

### Работать по расписанию

Вкладка **«Синхронизация»** показывает строку расписания:
`Автоскан: выключен · Автосинк: каждые 30 мин · следующий через 12 мин ·
последний 15:04`. Задаётся в **Настройки → «Расписание»**: два интервала
в минутах, 0 — выключено. Таймер считается **от открытия окна** и не
трогает занятую работу (идёт переиндексация или перенос — запуск отложится
на минуту).

Новые видео в очередь попадут только в режиме **«Полная»** — и тогда
качалка запустится сама.

**Без окна** (планировщик Windows):

```powershell
# полный цикл: переснапшот источников -> diff -> очередь -> скачивание
python omnistash.py --sync
python omnistash.py --scan      # отдельно: переиндексация хранилищ
```

```powershell
$action = New-ScheduledTaskAction -Execute "python.exe" `
  -Argument "-NoProfile omnistash.py --sync" -WorkingDirectory $PWD
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) `
  -RepetitionInterval (New-TimeSpan -Minutes 30)
Register-ScheduledTask -TaskName "Omnistash Sync" `
  -Action $action -Trigger $trigger -RunLevel Highest
```

Код возврата `--sync`: `0` — отработал, `1` — нечего синкать/ошибка
запуска, `2` — синк прошёл, но у части источников были ошибки. Всё, что
происходило, пишется в `omnistash.log`.

## Требования

- Windows 10/11 с WebView2 Runtime (по умолчанию входит в состав Edge).
- Python 3.12+ (для запуска из исходников).
- ffmpeg — **не входит в дистрибутив** (GPL: мы его не распространяем).
  Ставится кнопкой в настройках, раздел «Загрузка», и только с вашего
  согласия: сборка gyan.dev (зеркало — BtbN), встаёт в
  `%LOCALAPPDATA%\Omnistash\bin`. Ищется по цепочке: PATH → `bin\`
  рядом с программой → `%LOCALAPPDATA%\Omnistash\bin` → готовая копия
  Synfronia (второй раз не тащим). Без него качаются готовые потоки —
  без склейки, субтитров в файл и перекодировки.
- FTP/FTPS-сервер — понадобится с этапом M14 (выгрузка).

## Где что хранится

| Что | Где |
|---|---|
| Настройки, ключи | `%LOCALAPPDATA%\Omnistash\settings.json` |
| Индекс библиотеки | `%LOCALAPPDATA%\Omnistash\library.db` (SQLite + FTS5) |
| Хранилища (пути, метки, состояния) | в `library.db`, таблица `storages` |
| Журнал | `%LOCALAPPDATA%\Omnistash\omnistash.log` (ротация 1 МБ) |
| ffmpeg (если поставили кнопкой) | `%LOCALAPPDATA%\Omnistash\bin` (удаление папки = удаление) |
| Куки аккаунтов Google | `%LOCALAPPDATA%\Omnistash\accounts\*.bin` (зашифрованы DPAPI) + `accounts.json` (метки); «забыть» удаляет аккаунт |
| Незавершённая закачка | `.part` внутри самого хранилища |
| Готовая библиотека | ваши папки-хранилища (несколько, каждое включается отдельно) |

## Статус проекта

Работает сейчас:

- **Индекс на SQLite** — схема с миграциями, `raw_json` полных метаданных
  рядом с тонкими колонками под сортировку и фильтры, полнотекстовый
  поиск (FTS5), статусы `в индексе → в очереди → скачано → файл пропал →
  удалено на площадке`.
- **Переиндексация папок** — несколько корней; файл опознаётся по sidecar
  `post.json`, по ID в имени, по точному названию и по хешу содержимого
  (переезд = перепривязка того же файла, а не дубль).
- **Добавление плейлистов и каналов** — индексация с прогрессом (чанками,
  снапшот ничего не пишет) → диалог со счётчиками «новых / уже есть /
  пропущено» и выбором режима → поэтапное создание в одной транзакции
  (Плейлист → Авторы → Видео → Связи), отмена откатывает всё → итог с
  пикером ручного выбора.
- **Режимы синхронизации** — Полная (новое сразу в очередь), Частичная
  (метаданные + выбор контента), Ручная (только по кнопке).
- **Дерево «Пул / Каналы / Плейлисты»** — виртуальные узлы над таблицами
  (файлы при этом лежат по шаблону пути), виртуализированная таблица
  библиотеки, карточка метаданных с raw_json, журнал запусков.
- **Загрузчик и очередь** — очередь живёт в таблице и переживает рестарт
  окна; прогресс с процентом, скоростью и ETA; «Остановить» возвращает
  строку в очередь (`.part` остаётся для докачки), «Повторить упавшие» —
  одним нажатием; режим «Полная» стартует качалку сам. ffmpeg ищется по
  цепочке PATH → папка программы → профиль → папка Synfronia, при
  загрузке пишется sidecar `post.json` с хешем файла.
- **Эксплуатация** — причина падения видна прямо в строке очереди (плюс
  «повторить эту» у строки), очередь возобновляется при старте окна
  (настройка «Продолжать очередь при запуске»), а журнал пишется в
  `%LOCALAPPDATA%\Omnistash\omnistash.log` с ротацией до 1 МБ и
  открывается кнопкой в футере.
- **Синхронизация источников** — «Синхронизировать всё» переснимает каждый
  плейлист и канал, считает diff и применяет его: новые строки появляются
  в индексе, выпавшие помечаются убывшими (файл при этом не трогается),
  ошибка одной площадки не валит остальные. Итог — таблица по источникам
  с кнопкой «поставить новые в очередь», а режим «Полная» ставит их сам.

- **Хранилища вместо «одной папки»** — индекс привязан к нескольким
  папкам сразу (`storage_id` + относительный путь): переименовали диск —
  это смена пути за транзакцию, а не переписывание тысяч путей. Состояния
  «нет носителя» и «отвязано» отделены от «файл пропал», поэтому
  отключённый внешний диск не заваливает библиотеку потерями. Отвязка
  забывает папку целиком (спрашивая, оставить ли след), а повторное
  добавление восстанавливает файлы по сайдкарам/ID/названию. Первый
  запуск спрашивает «Где хранить видео?», выбор хранилища при загрузке —
  ручной (панель выделения, карточка, пикер).

- **Восстановление отвязанной папки** — отвязка забывает папку (спрашивая
  каждый раз, оставить ли след), а при повторном добавлении программа
  узнаёт её по маркеру `.omnistash-root` и предлагает **вернуть** её или
  **указать новый путь** (диск переименовали). Скан восстанавливает файлы
  по сайдкару → ID → названию и **дописывает недостающие `post.json`**
  опознанным файлам - каждая следующая переинициализация дешевле и не
  зависит от имён.

- **Сверка после скана: копии и переезды** — хеш файла сверяется с
  индексом, и теперь различаются три случая: настоящая **копия** (старый
  файл ещё на месте → вторая строка и раздел «Дубликаты»), настоящий
  **переезд** (старого файла нет → строка едет за файлом) и **«возможный
  переезд»** (старое хранилище недоступно → гадать нельзя: показываем
  вопрос «Переехал / Это копия»). Разбор закрывается кнопкой «Оставить
  выбранную»: лишние копии удаляются с диска вместе со своими сайдкарами,
  оставшийся файл не может потеряться (удаление не удалось — строка
  остаётся). Есть и ручная привязка файла к видео (`rebind_file`).

- **Перенос между хранилищами** — выделили строки → «Перенести…» →
  превью (файлов, объём, конфликты имён, уже на месте, не найдено) →
  копия кусками с прогрессом → **проверка контрольной суммой** → только
  затем строка переключается на новый путь и оригинал удаляется. Отмена
  в любой момент безопасна: недокопированная цель подчищается, источник
  цел, а уже перенесённое при повторе просто пропускается. Внутри
  `post.json` путь до видео обновляется автоматически.

- **Мультивыбор в библиотеке** — чекбоксы строк, панель «Выбрано: N ·
  Хранилище: … → Скачать»: группа строк уходит в очередь одним действием
  и в выбранную папку.
