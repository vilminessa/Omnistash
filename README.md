# Omnistash

Загрузка, синхронизация и организация архивного контента в одном окне:
добавьте автора или ссылку — Omnistash докачает недостающее, свежее
принесёт сам, а библиотеку разложит по папкам, метаданным и коллекциям.
Работает на Windows, **без аккаунтов, телеметрии и лишних настроек**.

## Идея проекта

Вокруг архивных площадок (pawarchive.pw и им подобных) накопилось много
разовых загрузчиков: каждый качает свою площадку, кладёт файлы, куда
попало, и на этом всё заканчивается. **Omnistash — не очередной
загрузчик, а дом для собранной библиотеки.** Три равные задачи:

1. **Загрузить** — всё новое и всё пропущенное с любого подключённого
   источника.
2. **Синхронизировать** — держать локальную копию и удалённое хранилище
   (NAS / MediaHub) в согласии: без дублей, с возобновлением после обрыва.
3. **Организовать** — превратить свалку файлов в каталог: переименование
   по шаблонам, метаданные, обложки, теги, дедупликация, коллекции и
   поиск.

Всё это живёт в одном окне и работает по расписанию — как часы, а не
как разовая команда.

## Возможности

### Источники

- **Адаптеры площадок** — подключение источника описывается конфигом
  (какой API, как авторизоваться, как пагинировать). Новая площадка
  добавляется файлом конфигурации, а не правкой кода.
- **Всё разное в одном списке** — посты автора, отдельные ссылки, списки
  из файла, выгрузки вида `service:id` и полные URL.
- **Единый вход** — у каждого источника свой режим входа: публичный API,
  cookie, токен. Ключи хранятся локально.

### Загрузка

- **Череда и очередь** — ссылки качаются по очереди, падение одной не
  останавливает остальные; у каждой строки виден результат: скачано,
  качается, в очереди, пропущено, ошибка.
- **Возобновление** — обрыв связи, закрытие окна, перезагрузка: закачка
  продолжается с места остановки, `index.jsonl` хранит, что уже взято.
- **Повторы** — автоматические ретраи с паузой, лимитом и «умным»
  распознаванием площадки, которая временно не отвечает.

### Синхронизация

- **Инкремент** — при каждом запуске сверяется, чего в библиотеке нет
  или чего не хватает, и докачивается только это.
- **Контроль целостности** — размер и контрольная сумма каждого файла:
  битая копия обнаруживается и перекачивается, а не «принимается на
  веру».
- **Удалённое хранилище** — выгрузка на FTP/FTPS (MediaHub, NAS) по
  шаблонам путей, вложенные каталоги создаются сами, есть проверка
  подключения и повторы.
- **Watchdog** — фоновая задача Windows поднимает синхронизацию сама,
  если та не запускалась по расписанию.

### Организация (библиотека)

- **Шаблоны имён** — путь и имя файла собираются из метаданных:
  `автор / дата / ID - название`, плюс свои правила на любую площадку.
- **Метаданные рядом с файлом** — к каждому посту сохраняются автор,
  дата, описание, ссылка на оригинал и обложка: `post.json` лежит рядом
  с содержимым, библиотека самодостаточна.
- **Дедупликация** — один и тот же файл, скачанный с разных площадок,
  распознаётся по хешу и не лежит в библиотеке дважды.
- **Коллекции и теги** — папки-подборки, собственные теги и быстрый
  поиск по автору, названию, дате и тегу без ожидания «провайдера
  файлов».
- **Переупаковка** — переименование и перенос уже собранной библиотеки
  по новым шаблонам (в фоне, с отменой).

### Интерфейс

- **Пять вкладок**: Источники · Загрузка · Синхронизация · Библиотека ·
  Журнал — состояние видно в одном окне.
- **Цветные статусы** — каждая строка очереди и каждый источник
  подсвечивают, что происходит прямо сейчас.
- **Внешний вид** — встроенные темы и свои, свой шрифт интерфейса,
  языки интерфейса (русский, английский).
- **Всё локально** — настройки, журнал и индекс лежат в
  `%LOCALAPPDATA%\Omnistash`, ничего не отправляется наружу.

## Как это работает

```
источник ──▶ очередь ──▶ staging ──▶ проверка ──▶ библиотека ──▶ хранилище
 (адаптер)   (список      (докачка    (хеш,       (шаблоны,     (FTPS/NAS,
              ссылок)      с resume)   дубли)      метаданные)   инкремент)
```

1. **Источник** отдаёт список того, что есть у автора.
2. **Загрузка** берёт по одному, кладёт в `staging\` и пишет `index.jsonl`.
3. **Проверка** сверяет размеры и хеши, отбрасывает битое и уже
   имеющееся.
4. **Организация** переносит файлы в библиотеку по шаблонам, рядом —
   `post.json` и обложка.
5. **Синхронизация** докачивает изменения на хранилище и отмечает
   выполненное.

Прервать можно на любом шаге — следующий запуск продолжит с того же
места.

## Как пользоваться

### Подключить источник

Вкладка **«Источники»** → *Добавить*: выбрать площадку, указать автора
(`service:id` или полный URL) и, если нужно, куда складывать. Источник
появляется в списке со своим статусом.

### Первая синхронизация

Вкладка **«Синхронизация»** → *Синхронизировать всё*: будет взято всё,
чего ещё нет в библиотеке. Для больших библиотек можно ограничить
запуск количеством постов и включить повтор при обрыве.

### Настроить организацию

Настройки → **«Организация»**: шаблон пути, что делать с обложками и
`post.json`, как искать дубли. Изменения применяются к новым загрузкам,
а кнопка *Переупаковать* переносит уже собранное.

### Выгрузить на хранилище

Настройки → **«Хранилище»**: включить выгрузку, указать сервер, порт,
логин, пароль, при желании FTPS и каталог (шаблоны вида
`media/{author}`, вложенные папки создаются сами). Кнопка
*«Проверить подключение»* прогоняет вход до конца.

### Работать по расписанию

Вкладка **«Журнал»** показывает ход задач, а watchdog через планировщик
Windows поднимает синхронизацию сам, если она не запускалась:

```powershell
$action = New-ScheduledTaskAction -Execute "python.exe" `
  -Argument "-NoProfile omnistash.py --sync" -WorkingDirectory $PWD
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) `
  -RepetitionInterval (New-TimeSpan -Minutes 30)
Register-ScheduledTask -TaskName "Omnistash Sync" `
  -Action $action -Trigger $trigger -RunLevel Highest
```

## Требования

- Windows 10/11 с WebView2 Runtime (по умолчанию входит в состав Edge).
- Python 3.12+ (для запуска из исходников).
- Для выгрузки — доступный FTP/FTPS-сервер (MediaHub, NAS).

## Где что хранится

| Что | Где |
|---|---|
| Настройки, ключи, темы | `%LOCALAPPDATA%\Omnistash` |
| Незавершённая закачка | `staging\` рядом с программой |
| Индекс загруженного | `index.jsonl` |
| Готовая библиотека | папка из настроек (`library\` по умолчанию) |

## Приватность

- **Без аккаунтов, телеметрии и аналитики** — серверной части нет.
- Всё состояние хранится локально; сеть используется только для того,
  что вы запросили: сами загрузки, ваше хранилище и проверка площадок.
- **Внимание**: ключи и FTP-пароль хранятся в настройках открытым
  текстом — не запускайте приложение на общем компьютере и не
  синхронизируйте папку настроек без шифрования.
