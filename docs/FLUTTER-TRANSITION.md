# Переход интерфейса Omnistash на Flutter (Impeller) с сохранением Python-бэкенда

Документ - план и записанные решения человека. Реализация идёт волнами W0-W6;
каждая волна - отдельный коммит, прогон офлайн-набора, сверка юр-пака и
бандла клиента, скан текстов на иностранные знаки и склейки латиницы с
кириллицей. Молчания нет: отказ волны называет причину и измеренные цифры.

## 1. Записанные решения

- Обёртка - **Flutter**, рендер **Impeller**. Факт из официальной
  документации Flutter (страница `docs.flutter.dev/perf/impeller`,
  отражает Flutter 3.47, обновлена 21.08.2026): Impeller доступен и включён
  по умолчанию на Windows, macOS и Linux начиная с 3.47; на iOS - единственный
  движок, на Android - по умолчанию с API 29+, на веб пока Skia. Отключение на
  Windows описано в `windows/runner/main.cpp` (`set_impeller_switch`), но план
  его не использует: цель - включить Impeller, а не обходить его.
- **Raven** (`github.com/oscar-soirey/Raven`) - только источник дизайна, не
  обёртка: нативная C/Vulkan GUI-библиотека с Python-биндингом, лицензия
  Apache-2.0 + файл `NOTICE`, версия 0.2.1 с публичным API «subject to
  change». Переносим токены темы (роли цвета, метрики, множители glass),
  генерацию палитры от акцента и проверку контраста WCAG; при перераспределении
  несём текст лицензии, copyright-notice и пометку изменений (Apache-2.0, п.4).
  Glass в Flutter - аппроксимация через `BackdropFilter`, и это названо
  аппроксимацией: Vulkan-шейдеры Raven не переносим.
- Переход **инкрементальный**: старое окно (pywebview + `ui_src`) живёт до
  закрытия parity-чеклиста; обе оболочки едут на одном Python-бэкенде через
  уже покрытый тестами HTTP-фасад (`POST /api/<имя>`, скоупы решает сервер,
  список целей сверяет `tests/test_ui_transport.py`). Откат любой волны -
  удаление её кода, поведение бэкенда не меняется.
- Два продукта и имена (решение человека, чтобы не путать с режимом `--serve`
  внутри программы):
  - **Omnistash** - полная версия: Python-бэкенд (окно, mesh, serve, выкачка),
    ставится установщиком;
  - **Stashroom** - клиентское решение: один exe на Flutter, просмотр
    подключённой библиотеки по HTTPS через привязанный токен (этап S6, пресет
    прав `viewer`), своей базы и mesh нет;
  - браузерная страница `/watch` остаётся третьим путём просмотра.
- Установщик - **Inno Setup 6** (исходники под Apache-2.0), деинсталятор с
  раздельными чекбоксами очистки. Скачивание «прочих частей» (ffmpeg и подобное)
  - **только кнопкой внутри программы**, как сейчас; установщик ничего не
  качает. Галочка в установщик для стороннего пакета добавляется только после
  юридического аудита его лицензии (решение человека).
- Плеер по умолчанию - браузерная `/watch` (вендорный `hls.js`, `Range`/HLS/
  субтитры покрыты тестами, ноль новых лицензий). Нативный плеер - отдельная
  spike-волна W4 с кандидатами и лицензионными гейтами (раздел 5).

## 2. Пути и состав продукта

| Продукт | Код и ассеты | Пользовательское состояние |
|---|---|---|
| Omnistash (полная) | `%ProgramData%\Omnistash\`: `Omnistash.exe` (бэкенд), `OmnistashUI.exe` (Flutter-окно), `LICENSE`, `THIRD_PARTY_NOTICES.md`, `licenses/`, ассеты UI | `%APPDATA%\Omnistash\`: настройки, база библиотеки, `legal.json`, mesh-идентичность, токены DPAPI; `%LOCALAPPDATA%\Omnistash\cache\`: миниатюры, HLS-кеш, временные части выкачки; `%APPDATA%\Omnistash\tools\`: скачанное по кнопке (ffmpeg, инструменты) |
| Stashroom (клиент) | один `Stashroom.exe`, без установки | `%APPDATA%\Stashroom\`: адрес сервера, привязанный токен, тема, язык, кеши миниатюр |

Деинсталятор Omnistash показывает раздельные чекбоксы: установочные файлы
(%ProgramData%), профиль (%APPDATA%: настройки, база, идентичность, юридические
факты), кеши (%LOCALAPPDATA%), скачанные инструменты. Файлы библиотеки
человека (его папки-корни) деинсталятор не трогает и говорит это в диалоге.

`legal.json`, mesh-ключи и токены под DPAPI живут в профиле пользователя;
очистка профиля удаляет их полностью - это называется в диалоге деинсталяции,
а не молча.

## 3. Волны и приёмка

### W0 - spike и цифры (производственные файлы не меняются)
Flutter-каркас, подключение к `--serve` loopback: доверие эфемерного TLS-
сертификата через сверку отпечатка ключа (тот же приём, что в mesh-канале),
локальный токен из профиля, вызовы `get_initial`, `list_videos`, `poll`,
`save_setting`. Измеряется на машине человека: время до первого кадра, RSS,
размер release-артефакта, поведение Impeller на реальном драйвере (Vulkan и
фолбэки), масштабирование 125%. Контрольный spike на Raven-биндинге даёт
сравнительные цифры и проверяет перенос токенов темы. Итог - таблица
измеренных чисел в этом документе; ничего не утверждается «по ощущению».

### W1 - дизайн-фундамент из Raven
Перенос ролей цвета, метрик, генерации палитры от акцента и проверки контраста
WCAG из темы Raven в `ThemeData` Flutter (Dart-код с пометкой изменений).
`docs/DESIGN-UI.md` остаётся контрактом Omnistash: шаги 1-7 (токены вместо
литералов, плотность и семантика списка, карточки каталога, панель мультивыбора,
диалоги со стеком/ловушкой Tab/Escape/возвратом фокуса/дефолт-отказом, веяния
только из токенов, `prefers-reduced-motion`) отображаются в `Semantics`
Flutter. Движение - пружины через `SpringSimulation`. Шрифт выбирается из
сабсетов Raven (Roboto - Apache-2.0, в Raven это модифицированный сабсет;
Instrument Sans / Bricolage Grotesque / JetBrains Mono - SIL OFL 1.1 из
инструментов Raven) и пинится по sha256 по образцу `ui_src/vendor` (рантайм
ничего не качает). Юр-записи Raven, Flutter, Dart и шрифтов добавляются в
`THIRD_PARTY_NOTICES.md` и в карту `licenses/manifest.json`; машина LC2
(юр-пак, вшивание, сверка состава по TOC) расширяется теми же стражами.

**Решение человека (05.11.2026): две темы, выбор в настройках.** Существующая
палитра `app/themes.py` остаётся токенами окна (тёмная, светлая, контрастная,
своя), к ней добавлена тема «Бренд» - вывод из палитры coolors по порогам WCAG
(`tools/build_brand_theme.py`, сверка `tests/test_brand_theme.py`: реестр
совпадает с выводом переменная-в-переменная, пары `CONTRAST_PAIRS` выдержаны,
роли различимы между собой, вне палитры ни одной hex-переменной, а списки
`app.css`, `THEME_IDS` и `choices` схемы настроек повторяют `themes.ids()` и
`themes.labels()`). Бренд-тема светлая по измеренной причине: `#C1121F` на
`#003049` даёт 2.22 - ниже порога 3.0 для значимой графики (SC 1.4.11),
значит акцентом на тёмной navy-подложке красным быть нельзя; на cream-подложке
тот же цвет держит 5.51. Производные tint выводятся в сторону navy там, где
базовый цвет порога не выдерживает, и каждый вывод сверяется валидатором
реестра, а не глазами.

Flutter W1 строит `ThemeData` из тех же ролей, а не из hex-литералов, и
одинаковым выбором темы в настройках: Dart-карта ролей цвета сверяется
mirror-стражем по образцу `tests/test_ui_settings_mirror.py` с `themes.ids()`,
`themes.labels()` и `CONTRAST_PAIRS`, битое значение настройки возвращает
дефолтную тему - как `themes.normalize` на стороне бэкенда.

**Сделано на волне W1 (прогон 06.11.2026, коммит `a1dda62`):** токены выводятся
`tools/build_flutter_theme.py` из реестра тем (28 ролей на тему, 5 тем,
`themes.CONTRAST_PAIRS` - 33 пары), из блока `:root` в `ui_src/app.css` (40
метрик: шаг отступов, радиусы, цели и контролы, типографика, длительности и
кривые `cubic-bezier`, две ширины кольца фокуса - см. ниже) и из констант `app/themes.py` (границы шрифта
10..22 px, масштаб 100..200 %, `ROW_MIN` 34, `ROW_FACTOR` 2.6); ассет
`ui_flutter/lib/theme_tokens.dart` детерминирован и сверяется с генерацией
байт-в-байт (`--check`); `ui_flutter/lib/theme.dart` строит `ThemeData` из
ролей - соответствие ролей на Material названо в комментарии файла,
`ThemeData` не держит hex-литералов, размеров и длительностей числом;
`tools/check_flutter_mirror.py` + `tests/test_flutter_mirror.py` (13 проверок
на момент шага W1; сейчас 52 - см. §W2 ниже) сверяют Dart с реестром, CSS,
константами шрифта, парами контраста и `choices` поля `theme`, и гоняются на GitHub-раннере без Flutter SDK; на
стороне Flutter `ui_flutter/test/theme_test.dart` (8 проверок) считает
контрасты перенесённой формулой WCAG и сверяет подложку, разделитель,
границу контрола, яркость, радиусы, размеры текста и формулу высоты строки.

Что на W1 осталось и названо причиной: генерация палитры от акцента и
множители glass из Raven (Apache-2.0 + NOTICE + пометки изменений) не
переносимы до аудита лицензии и пина версий; шрифты Raven-сабсетов (Roboto -
Apache-2.0, Instrument Sans / Bricolage Grotesque / JetBrains Mono - SIL OFL
1.1) кладутся и пинятся по sha256 только после аудита (`docs/LEGAL-REVIEW.md
§5 «Отложить»`), до аудита Dart держит системный стек и ничего не качает;
строки `box-shadow` не переносятся «строка-в-строку» - Flutter строит
elevation своими объектами, форма тени ложится на волне W3; на шаге W2 3
`--veil` перенесён числом (ARGB альфа и цвет каждой темы - `kThemeVeils` ->
`veilColor`), `--focus-ring` - двумя ширинами px (`focusRingGap`,
`focusRingFocus`, цвета читаются из ролей `--bg` и `--focus`), форма кольца -
border вместо двух box-shadow, названо расхождением; `Semantics` строк
списка построена на шаге W2 (ниже), табы - на шаге W2 2, карточка видео и
диалог §3.8 - на шаге W2 3 (ниже), стек диалогов и редактор пометок - W3;
golden-тесты не построены
и названо почему: pixel-сверка зависит от GPU и драйвера и снимается только на
машине человека (GitHub-раннер UI-тесты не гоняет), поэтому структурная
сверка семантики и токенов ведётся widget-тестами и mirror-стражем; выбор
движка решён человеком на волне W2 (06.11.2026): продуктовое окно - Skia,
цифры обеих веток сняты в §9 и решение записано там же.

## 6. Риски (названные)

- Impeller на Windows зависит от Vulkan-драйвера и фолбэков: меряется в W0 на
  машине человека; GitHub-раннер UI-тесты не гоняет и не проверяет Impeller.
- Размер полной сборки вырастет (Flutter runtime добавляет десятки МБ к
  текущим ~30 МБ): правки документов называют измеренные значения прогона,
  нижняя граница 20 МБ остаётся сверяемой формулировкой.
- Supply-chain: Flutter SDK, pub-пакеты и Inno Setup пинятся версией и sha256;
  рантайм по-прежнему ничего не скачивает сам.
- Доступность: Flutter Semantics не равен ARIA; parity-чеклист под Narrator
  отдельная работа.
- Raven 0.2.1 с меняющимся API: если он остаётся только дизайн-источником,
  риск ограничивается пинком версии на дату переноса токенов.
- Два клиента на одном бэкенде: риск расхождения текстов и прав - mitigation
  единый источник schema/i18n/scopes и mirror-стражи на Dart.
- Нативный плеер: лицензионная цепочка mpv/LGPL, FFmpeg без GPL, libass ISC;
  решение принимается после аудита и цифр W4, до решения в артефактах этих
  компонентов нет.

## 9. W0: измеренные цифры (машина человека, 05.11.2026)

Цифры берутся прогоном, не ощущением. Стенд: `build/scratch/spike/measure.py`
(mock TLS-сервер, Flutter-окно, базовое окно pywebview + WebView2) и
spike-окно `ui_flutter/` - каркас коммичен по решению человека и README
называет его измерительным стендом; производственные экраны пишутся на волне
W2, а окна мерятся тем же стендом.

| метрика | Flutter-окно | текущее окно (pywebview + WebView2) |
|---|---|---|
| первый кадр | 17-19 мс (три прогона: 19, 17, 18) | `create_window` 2 мс; событийный цикл готов 772-1144 мс (прогоны: 772, 902, 976, 1144) |
| автопрокрутка 2000 строк за 3 с | 135-138 кадров, 45-46 fps; вызовов `itemBuilder` 2121-2146 за прогон (виртуализация: часть строк перестроится при прокрутке) | прокрутка в базовом замере не измеряется; полный цикл окна 4289-4583 мс |
| вызов фасада по TLS | `list_videos` 41-53 мс, `poll` каждые 500 мс без отказов (отказов в журнале прогона нет) | - |
| рабочий набор (пик, дерево процессов) | 123.5-126.3 МБ | 378.7 МБ |
| размер release-артефакта | бандл 25.5 МБ, exe 0.1 МБ | - |

Транспорт сверен проводкой: TLS 1.3, шифр `TLS_AES_256_GCM_SHA384` на
loopback; доверие по пину DER sha256 (серверный сертификат эфемерный, пин
привязан к одному прогону); тело передаётся с явным `Content-Length` - без
него Dart отправляет chunked, и сервер, читающий `Content-Length`, получил бы
0 байт. Скоупы здесь не решаются: mock называет проводку, права решает
`app/http/server.py` (сверяются Python-набором).

A/B рендерера на пересобранном бинаре: переключатель выставляется в runner
явно (`project.set_impeller_switch` из обёртки `flutter::DartProject`), потому
что аргументы командной строки runner передаёт как аргументы Dart-точки входа
и они не меняют настройку движка. Список модулей процесса берётся через
`Get-Process` (Toolhelp-структура `MODULEENTRY32W` в разных Windows SDK
расположена по-разному, имя поля читалось пустым).

| настройка | первый кадр | fps при автопрокрутке | рабочий набор (пик) | модулей | что печатает движок |
|---|---|---|---|---|---|
| дефолт платформы (без настройки) | 16 мс | 49.3 | 111.2 МБ | 78 | `Using the Impeller rendering backend (OpenGLESSDF)` |
| `EnabledImpeller` | 17 мс | 51.7 | 114.9 МБ | 78 | та же строка |
| `DisabledImpeller` | 17 мс | 60.0 | 76.8 МБ | 78 | строки про Impeller нет (путь Skia) |

Загруженные графические библиотеки во всех трёх настройках одинаковые:
`opengl32.dll`, `glu32.dll`, `d3d11.dll`, `d3d9.dll`, `d3dcompiler_47.dll`,
`d3dscache.dll`, `dxgi.dll`; `vulkan-1.dll` не загружается ни в одной, хотя
Vulkan на машине доступен (`vulkaninfo`: AMD Radeon Graphics, apiVersion
1.3.260, версия instance 1.3.301).

Три измеренных вывода. Первый: дефолт платформы совпадает с включённым
Impeller по числам, по набору модулей и по строке движка - значит
«Impeller включён по умолчанию на Windows с 3.47» подтверждён поведением, а
не цитатой из документации. Второй: имя пути рендера на этой машине названо
самим движком - Impeller работает на OpenGL-бэкенде (сообщение
`embedder_surface_gl_impeller.cc`: `Using the Impeller rendering backend
(OpenGLESSDF)`), Vulkan не задействован; вопрос «каким путём рисует» закрыт
на этой машине и остаётся открытым для других GPU и драйверов. Третий: на
этой машине Skia-путь (`DisabledImpeller`) при прокрутке списка быстрее и
дешевле по памяти (60.0 fps против 49.3-51.7, 76.8 МБ против 111-115 МБ).
Решение человека от 06.11.2026: продуктовое окно строится на Skia - в
`ui_flutter/windows/runner/main.cpp` без spike-флага ставится
`set_impeller_switch(Disabled)`; стенд W0 (`OMNISTASH_SPIKE=1`) держит
default - Impeller, иначе числа выше описывали бы уже не ту ветку, под
которой они сняты; ветки стенда переключаются и явно
(`OMNISTASH_IMPELLER=on/off`). `flutter build windows` не принимает
`--no-enable-impeller` в этом SDK (отказ назван прогоном: `Could not find an
option named "--no-enable-impeller"`), поэтому выбор движка лежит в runner
как engine- switch, а не в команде сборки. Мерка факта после правки
(коммит `d82ef1e`): сборка release 29.5 с; живой прогон экрана против
`--serve` (`live_serve.py --production` без spike-флага) - stderr пуст
(строка `Using the Impeller rendering backend (OpenGLESSDF)` исчезла - Skia
её не печатает), журнал аудита пишет те же цели кодом 200 правом `read`
(`get_initial`, `list_videos`, `poll`) - смена движка не меняет транспорт и
права.

Пересъёмка после переноса токенов темы (W1, прогон 06.11.2026, тот же бинарь и
тот же стенд: `python build/scratch/spike/measure.py --themes`, два прогона на
тему; стенд переключает тему переменной окружения `OMNISTASH_SPIKE_THEME`,
высота ряда стенда - `OMNISTASH_SPIKE_ROW_EXTENT`, дефолт 44 px, и числа выше
описывают именно этот geometry):

| тема | яркость | первый кадр (два прогона) | fps при автопрокрутке 2000 строк | рабочий набор (пик, дерево) | фасад по TLS |
|---|---|---|---|---|---|
| `dark` | тёмная | 14 и 13 мс | 47.3 и 48.3 | 128.3 и 128.3 МБ | 76 и 39 мс |
| `light` | светлая | 15 и 15 мс | 48.3 и 49.7 | 131.1 и 121.0 МБ | 54 и 47 мс |
| `coolors` («Бренд») | светлая | 16 и 14 мс | 49.0 и 45.0 | 121.1 и 128.2 МБ | 41 и 37 мс |
| `contrast` | тёмная | 14 и 14 мс | 48.0 и 47.3 | 128.6 и 123.4 МБ | 58 и 37 мс |
| `custom` | тёмная | 14 и 12 мс | 47.7 и 46.7 | 127.6 и 128.0 МБ | 73 и 39 мс |

Перенос токенов не меняет наблюдаемых чисел: все пять тем держат тот же
диапазон, что таблицы выше (первый кадр 12-20 мс, 45-51.7 fps, 105-132 МБ), и
строка движка во всех темах одна - `Using the Impeller rendering backend
(OpenGLESSDF)`. Единичный прогон перед этой пересъёмкой показал первый кадр
30 мс - назван выбросом того же бинаря, а не регрессией токенов: два прогона
на тему дают 12-16 мс. Латентность фасада в таблице - один вызов `list_videos`
на mock-сервере; живые цели и их латентность с правами ключа мерятся отдельно
(`--pinrefuse` ниже и `live_serve.py`).

Отказ при несовпавшем пине измерен отдельно
(`python build/scratch/spike/measure.py --pinrefuse`: тот же mock-сервер,
пин заведомо другой - отпечаток SPKI вместо DER-хеша). Клиент отвергает
канал и называет причину дважды: в stderr -
`TLS: отпечаток сертификата <sha256> не совпал с пином <sha256> - отказ`, в
сводке окна - `poll: канал не открыт: HandshakeException: ...
CERTIFICATE_VERIFY_FAILED: self signed certificate`. Молчания нет: отказ
виден и как причина TLS, и как отсутствие вызова фасада (`facade_ms: -1`).

Вызовы к живому `--serve` измерены (`python build/scratch/spike/live_serve.py`:
настоящий `app.http.server.ServeServer` в временном профиле, реестр токенов и
журнал аудита там же, доверие по DER-пину эфемерного сертификата):

| ключ | цель | ответ сервера | латентность |
|---|---|---|---|
| полный (`read, queue, mark, sources, mesh, accounts, server_config`) | `get_initial` | 200, право read | 40-44 мс |
| полный | `list_videos` | 200, право read | 13-16 мс |
| полный | `poll` | 200, право read | 58-68 мс |
| полный | `bulk_rating` | 200, право mark | 12 мс |
| читатель (`read, watch`) | `get_initial`, `list_videos` | 200, право read | 40 мс и 16 мс |
| читатель | `save_setting` | 403, право server_config | 11 мс |

Отказ скоупа назван сервером и виден в журнале аудита:
`ключ читатель метод save_setting код 403 право server_config`, текст
ответа - `не выдан скоуп server_config` с `code: scope`. Права решает
сервер, клиент только называет цель - это и проверялось.

В прогоне есть названный шум: сервер пишет
`HTTP-сервер: соединение от 127.0.0.1 отклонено: SSLEOFError` - это
обрыв соединения, когда стенд убивает процесс окна посреди запроса, а не
отказ доверия; он печатается сервером как причина и не влияет на коды
ответов в журнале.

Контракт проводки сверен с канонным источником
(`ui_src/app.js:547` и `app/http/server.py: _body`): цель без аргумента
отправляет тело `{}`, цель с аргументом - `[аргумент]`. Первая версия
спайка отправляла `[{}]` на `get_initial` и получала 400
`битый запрос ... takes 1 positional argument but 2 were given` - сервер был
прав, неправ был стенд. Вторая ошибка стенда: mock отвечал `videos`, а
фасад отвечает `rows` (`app/gui.py list_videos`) - canned-форма ввела
`bulk_rating` в заблуждение («Ничего не выбрано»), и mock теперь повторяет
форму фасада. Отказ фасада внутри 200 с полем `error`
спайк считает отказом с текстом причины, а не успехом.

системный DPI человека не менялся):

| размер окна | первый кадр | fps при автопрокрутке | рабочий набор (пик) |
|---|---|---|---|
| 1280x720 (базовый) | 15 мс | 50.7 | 128.0 МБ |
| 1600x900 (эквивалент 125% по числу пикселей: 1.5625x) | 18 мс | 48.0 | 158.6 МБ |
| 1920x1080 (эквивалент 150%: 2.25x) | 20 мс | 49.3 | 179.0 МБ |

Первый прогон этих трёх строк мерился на старом бинаре: сборка с
`getenv` не прошла (MSVC считает его deprecated и ставит warning как
ошибка), числа были сняты до пересборки и отвергнуты. Чтение окружения
переписано на Win32 `GetEnvironmentVariableA`, сборка прошла, таблица
снята на новом бинаре.

Impeller на этой машине назван не измеренным: процесс не загружает
`vulkan-1.dll`, загружает `OPENGL32.dll`, `GLU32.dll`, `d3d11.dll`,
`d3d9.dll`, `dxgi.dll`, `dcomp.dll`; Vulkan runtime на машине доступен
(`vulkaninfo`: AMD Radeon Graphics, apiVersion 1.3.260, версия instance
1.3.301). По списку модулей и по A/B нельзя сказать, какой бэкенд
используется - Impeller-D3D или Skia - поэтому это остаётся открытым
пунктом W0, а не утверждением «Impeller включён».

Что ещё не измерено и называется явно: поведение на других GPU и драйверах
(имя бэкенда сверено только на этой машине) и контрольный spike на Raven.
Включённость Impeller, имя пути рендера на этой машине, пиксельная нагрузка,
латентность фасада на живом `--serve` и по правам ключа, рабочий набор,
проводка контракта `{}` против `[аргумент]` и отказ по несовпавшему пину -
измерены. Системный DPI человека не менялся: вместо него измерена пиксельная
нагрузка эквивалентного размера окна (таблица ниже).

Починки стенда, найденные прогоном (не «по ощущению»): mock TLS оборачивал
слушающий сокет, а `accept()` возвращает открытый сокет - рукопожатие
перенесено на принятое соединение, как в `app/http/server.py`; обработчик
mock терял строку чтения пути и падал с `NameError`, что выглядело как
закрытие канала; счётчик RSS требовал полный `PROCESS_MEMORY_COUNTERS`
(укороченная структура даёт ошибку 122) и отдельный поток выборки (в основном
потоке `readline` блокирует цикл, и пик терялся); базовое окно мерится по
дереву процессов, потому что WebView2 живёт в дочерних
`msedgewebview2.exe`.
