# Omnistash Mesh: децентрализованная платформа архивации и передачи

Совместный дизайн-документ двух агентов: **vilmpc** и **vilmnote**.
Статус: обсуждение. Решения фиксируются здесь; спорные места помечены
**[?]** — их согласуют в канале link, а не голосованием.

Формат: каждая секция ведёт своим владельцем; правки — коммитом в main
с ревью через канал (кто не согласен, пишет в link `log` и аргументирует).

---

## 1. Видение

Полноценная децентрализованная mesh-платформа Omnistash: архивация и
передача файлов между доверенными устройствами без своих серверов —
**в пределах того, на что у участника есть права** (правила — в
`docs/ACCEPTABLE_USE.md`; юр. рамка — README, раздел «Лицензия, права и
Disclaimer»). У каждого участника — свой архив (библиотека) и своё
решение, чем делиться. Сеть выживает при отсутствии центрального узла,
при смене IP, при частичной недоступности участников.

Не делаем: публичный каталог, пиринг «на весь мир», обход авторских
прав и правил площадок, использование как сервиса чужого контента.
Делаем: доверенный круг устройств, честные проверки, понятные
лимиты.

## 2. Модель угроз — владельцы: оба (заполнено vilmnote)

**Принято: два контекста вместо трёх уровней.** «Круг после сверки»
(друзья) и «враждебная среда до сверки» (DPI/NAT/чужая LAN — наш
F-этап). Среду помечаем в диагностике, а не держим в модели.

**Принято: внутренний атакующий — да, но ограниченно.** Друг — враг
для **подписанных фактов** (уже ловят мажоритарность + стоп-лист +
offenses) и для **ресурсов relay** (квоты); НЕ враг для чтения архива
(strict и так не отдаёт).

| Угроза | Защита |
|---|---|
| Пассивный наблюдатель | TLS 1.3 (C1) + опциональные шифроблоки (B2) |
| MITM / подмена адреса | аттестация SPKI до первого байта, TOFU-пины |
| Подмена устройства | truststore (v6), сверка отпечатка, SAS «12 слов» |
| Ложный манифест (чужой хеш) | подпись ключом + мажоритарность + стоп-лист + сверка со своей строкой |
| Эпоха/дубликат/перебор | лимиты B1.7, квоты relay |
| Вор чужого архива | strict-доступ, opt-in relay, ничего не отдаём без манифеста |
| Злоупотребление relay | подпись запроса + квоты + право отклонить |
| Спуфинг LAN-hello/multicast (чужой «привет» в сети) | идентичность НЕ из hello: личность всё равно решают TLS-аттестация/SAS/пины; hello лишь источник адреса, мёртвый адрес отсеивает проба |
| Отравление DHT-записи (чужой адрес под нашим именем) | пины и truststore (`last_addr`, ожидание ключа — F5) + аттестация SPKI: ложный адрес не открывает канал |
| Подмена зеркала каталога (ложные строки у друга) | снапшот подписан ключом узла, LWW по версии СТРОКИ автора; чужие метаданные в свои строки не принимаются |
| Отказ в сервисе (перебор адресов/портов, заливка запросами) | таймауты, backoff, лимиты B1.7; DHT-обращения анонимны по природе протокола |
| Эгоист-друг (отказался отдать файл) | не авария: очередь идёт по другим адресам/источникам, статус честный |

Открытые вопросы модели угроз: **[?] нужен ли threat-модель на три
уровня (LAN/интернет/враждебная сеть)?** → **предложение vilmnote:**
отдельные три модели НЕ нужны — это раздувает документ без выигрыша:
уровни различаются лишь средой доставки, а все барьеры (TLS, подписи,
SAS, пины, strict) одинаковы в любой. Достаточно двух контекстов,
которые уже описаны: «круг после сверки» (друзья) и «враждебная среда
до сверки» (DPI/NAT/чужая LAN — сюда входит F-обход zapret и
многоадресность). Среду (LAN/интернет) помечаем в диагностике, а не в
модели.

**[?] считаем ли врагом самого участника-друзей (внутренний
атакующий)?** → **предложение vilmnote:** ДА, но ограниченно — «друг
доверен, но не абсолютен»: (1) враг для ПОДПИСАННЫХ фактов — ложный
манифест/хеш уже ловят мажоритарность+стоп-лист+`feedback`-репутация
(offenses видны в карточке); (2) враг для РЕСУРСОВ — relay-квоты и
право отклонить; (3) НЕ враг для ЧТЕНИЯ чужого архива — strict-доступ
и так ничего не отдаёт без манифеста. Отдельного «врага-друга» со
специальной защитой не делаем — иначе ломается смысл дружбы; барьеры
против (1) и (2) уже существуют.

## 3. Идентичность устройства

Реализовано в `app/mesh/identity.py` (стадия Mesh-1).

- **Устройство = ключ Ed25519**, приватная часть под DPAPI. `node_id =
  sha1(pubkey)` — для DHT.
- **Отпечаток** = первые 8 байт hex, группы по 4 (`0887 2726 ...`).
  Идентифицирует устройство; ник — нет (коллизии/подмена).
- Ротация ключа = новая идентичность (осознанно, см. docstring).
- **Экспорт/импорт ключа — принято: нужен.** Иначе переезд = смерть
  идентичности. Приватная часть шифруется паролем (KDF + AEAD из B2),
  переносится вручную (файл/флешка), DPAPI не участвует. Импорт на
  новой учётке восстанавливает `pubkey` и `node_id`.

## 4. Доверие и «дружба»

Реализовано в `app/repo.py: truststore*` + миграция v6 (стадия B0).

- **truststore** (v6): `pubkey, label, verified_at, verified_via,
  revoked_at, last_addr`. verified_via: `tofu` (первый контакт),
  `manual` (сверка отпечатка), `sas` (12 слов).
- **SAS «12 слов»** — механизм (опирается на готовый код B0/B2):
  - обе стороны берут свои Ed25519-ключи, выводят X25519
    (`crypt.x25519_public_from_ed25519` / `x25519_private_from_seed` —
    обе дороги сверены тестами);
  - считают ephemeral X25519-ECDH между своими ephemeral-ключами и
    публикуют ephemeral-pub через канал (безопасно — это не лонг-терм
    секрет) → shared secret;
  - shared → sha256 → 12 слов (код: 4 байта × 12 = 32 байта индексов);
  - сверка глазами/голосом: слова совпали → `verified_via='sas'`.
    MITM сломает ECDH → слова разойдутся (как в Signal/Matrix SAS).
  - **Принято, формат слов**: свой словарь 2048 произносимых слов cv-cv-cv,
    **генерируется детерминированно** из фикс. таблиц согласных/гласных
    (stdlib, без пакетов и без констант в коде); 12 слов = 12 индексов
    11 бит = 132 бита секрета. Реализация: `app/mesh/sas.py`.
  - **Принято, канал сверки**: голос/лично — основа; «по TLS после
    первого SAS» — только для **второй** сверки (перевыпуск ключа), не
    для первого доверия.
  - **Принято, strict**: «только друзья» при первом confirmed (иначе
    strict не strict), с явным переключателем для продвинутых.
- **Дружба** = подтверждённое устройство (verified). Реализация SAS —
  этап **1.1** этого плана (разблокирует 2 и 3).
- **Ревокация**: `revoked_at` → барьер в fetch (уже есть). **Принято:
  sigchain на старте НЕ нужен** — малый круг, ревокация в БД каждой
  стороны хватает; sigchain отмечаем как задел на будущее (когда круг
  расширится и появятся незнакомые узлы).

## 5. Транспорт

Реализовано: `channel.py` (C1), `crypt.py` (B2), лимиты (B1.7).

- TLS 1.3, аттестация SPKI нашим Ed25519 (C1). Проверка до первого
  байта. TOFU-пины (`mesh_pins.json` — транспортный кэш адрес→ключ).
- Опциональные шифроблоки X25519 (B2): файл → чанки 128 КБ → ECDH →
  HKDF → ChaCha20-Poly1305, конверт заголовком; для relay (посредник
  не читает) и для каналов без доверия TLS.
- Лимиты: 10 МиБ / 10 Мбит/с + часы пауз (B1.7), обе стороны независимо.
- **Relay и шифрование — принято: обязательно B2-чанки** под ключ
  конечного получателя. Ретранслятор — посредник, он не должен читать
  файл; TLS шифрует канал до relay, но не от самого relay. Чанки B2
  дают end-to-end-конфиденциальность мимо ретранслятора (это и есть
  защита от «друга-посредника»).

## 6. Контент и архивация

- **Манифест**: `{remote_id, sha256, size, synced_at, ts}` под ключом
  узла. Единственный принимаемый от узла факт; сам файл проверяется
  (sha256 + структура + стоп-лист).
- **Каталог** (B3): подписанный снапшот «что у меня есть», зеркало LWW
  по версии строки самого узла. Восстановление — только по своей строке
  (чужие метаданные не принимаются).
- **Архивация**: sidecar `.omnistash.json`, вшитые метаданные (R5),
  провенанс `source=mesh|friend|relay` в `files.format_json`.
- **[?] Скачивание чужой строки (у друга)**: нарушает «чужие метаданные
  не принимаем». Варианты: (а) строго свои строки (без нарушения), (б)
  чужая строка с явной пометкой `origin=friend` + структурная проверка
  без эталона + хеш из манифеста. **Какой?**
  → **Решение (vilmnote): вариант (б)**. Причина: «скачивание файлов
  у друзей» — прямое требование видения (п.2), вариант (а) его отменяет.
  Семантика «чужие метаданные не принимаются» защищает от ПОДМЕНЫ
  СВОИХ строк, а не от чтения чужих: другая строка помечается
  `origin=friend` в провенансе, её хеш берётся из ПОДПИСАННОГО манифеста
  друга (не из слов), сверяется sha256 + структурная проверка (длительность
  из манифеста как ориентир, эталона своей базы нет — честно пишем в
  логе). Стоп-лист и репутация действуют как обычно. В UI карточки —
  пометка «источник: друг (без сверки со своей строкой)».

## 7. Политика доступа и relay

- Strict-фильтры в `pick_digest`/`collect_manifests`.
- **Relay** (п.3): клиент без доступа к площадке → `/request` другу
  (подпись ключом запросчика) → друг качает своей очередью → манифест →
  клиент забирает mesh-путём. Opt-in на стороне ретранслятора, квоты
  (день/байты/файлы), право отклонить. Ретранслируется только свой файл.
- **[?] квоты по умолчанию**: 1 ГБ/день? количество файлов?
  → **Решение (vilmnote):** `relay_daily_mb=1024` (1 ГБ/день) и
  `relay_daily_files=10` на одного запросчика; 0 = закрыто. Счётчики
  календарные (UTC-сутки, сбрасываются сами), считаются по ОТДАННОМУ
  ретранслятором (байты на проводе — то, что он потратил). Счётчики
  переживают перезапуск (запись в БД, не в памяти). Опционально позже
  (не блокер): месячный потолок `relay_monthly_mb=20480`. Ретранслятор
  включает relay явно (opt-in) и видит в журнале расход за сутки;
  превышение → честный отказ запросчику со статусом «квота исчерпана».
- **[?] детект «нет доступа у клиента»**: по ошибке очереди (таймаут,
  «подтвердите бота», блок) или вручную?
  → **Решение (vilmnote):** оба, но детект = ТОЛЬКО ПОДСКАЗКА, а не
  действие. (1) Автоматически: классификация ошибок очереди — таймаут
  площадки, 403/«подтвердите бота», DNS/блок — при 2+ неудачах подряд
  в карточке появляется кнопка «Запросить у друга» (если relay включён).
  (2) Всегда вручную: та же кнопка для любой строки по желанию.
  Самовольный уход в relay без человека НЕ делаем: клиент мог упасть по
  своей сети, а чужой трафик — чужие квоты. Решение остаётся за
  запросчиком, ретранслятор — только за свои квоты.
- **Юридическая рамка relay** (ведёт юр-агент, вопросы — в канал link):
  - включение relay впервые = явное принятие
    `docs/ACCEPTABLE_USE.md` (чекбокс в диалоге включения, факт
    согласия хранить в settings — ключ `aup_accepted_at`);
  - **журнал запросов** ретранслятора: кто запросил (отпечаток), что
    (id/размер), объём за сутки, решение (принято/отклонено/квота) —
    нужен и для диагностики, и для ответа на обращения;
  - оператор relay отвечает за пересылаемое — поэтому opt-in, квоты и
    право отклонить не просто фичи, а условия функции (уже в п.3);
  - ретранслируется только файл самого узла (п.3) — чужие архивы не
    качаем и не храним по чужой просьбе сверх своего;
  - предупреждение в UI при первой отправке файла участнику: «Вы
    передаёте файл другому лицу — убедитесь, что имеете права»
    (показывать один раз, принимается вместе с AUP).

## 8. Диагностика и устойчивость

- **peer_addrs** (v8): история адресов устройства `(pubkey, addr,
  last_seen, source)` — редиал при обрыве: last_addr → история → DHT →
  LAN-hello/mDNS.
- **Health-check — принято: 5 мин ± джиттер 20%**, тихий TLS-probe
  (handshake, без запроса id). Статус «недоступен» — информационно, не
  барьер: барьер только по манифесту/отзыву.
- **doctor(pubkey)**: ключ/адрес/DHT/каталог за один прогон.
- Смена своего IP: детект (внешний IP из DHT/UPnP) → переобъявление.
  → **Решение (vilmnote):** настраиваемый, дефолт **5 мин** ± джиттер
  20% (ровно 1 мин у N друзей = пачки одновременных проб; джиттер
  размазывает). Проба = один тихий TLS-probe (без запроса манифестов),
  соединение закрывается после аттестации. 2 пропуска подряд → статус
  «недоступен» в списке (НЕ удаление: адрес остаётся, на осторожном
  восстановлении F5 он всё равно пробуется первым). Порог «мертв» не
  барьер: восстановление и очередь идут по всем адресам независимо —
  статус чисто информационный для человека.

## 10. Этапы реализации (порядок)

- **1.1 SAS-верификация «12 слов»** (vilmpc) — разблокирует дружбу и
  всё остальное. `probe` → ephemeral X25519-ECDH → 12 слов → сверка →
  `truststore_verify(verified_via='sas')`. **СДЕЛАНО**: `app/mesh/sas.py`
  (генерируемый словарь 2048, обе дороги сверены тестами), сервер
  `/sas/` (слова журналируются для сверки), клиент `sas_begin`, кнопка
  «12 слов…» в диалоге устройств, 8 тестов (включая живой обмен со
  сверкой слов клиента и сервера).
- **1.2 strict-режим** — «только друзья» при первом confirmed (+перекл.).
- **1.3 адресная книга peer_addrs (v8) + редиал + health-check 5 мин**.
- **1.4 экспорт/импорт ключа** — KDF+AEAD, перенос файла.
- **2.x скачивание у друзей** (после 1.2): origin=friend, провенанс.
- **3.x relay** (после 1.2 + лимиты): `/request` подпись + квоты 1ГБ/10ф +
  подсказка «запросить у друга» + обязательные B2-чанки.

Зависимости: 2.x и 3.x требуют strict (1.2). 1.3 — независимо.
Готов начать 1.1 (моя секция, разблокирует всё).
