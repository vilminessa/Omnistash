> Все цитаты — из первоисточников (2025–2026); ссылки в конце каждого раздела.

## 1. Оценка рисков по категориям (severity)

Шкала: **низкий / средний / высокий / критический** — по совокупности «вероятность × тяжёлые последствия для автора проекта».

### 1.1 Copyright / выкачка контента с площадок — **высокий**

Факты из первоисточников:
- YouTube ToS («Permissions and Restrictions», п.1): вы не вправе «access, reproduce, **download**, distribute … any Content» кроме как (a) прямо разрешённого сервисом, (b) с письменного разрешения YouTube и правообладателя, (c) «as permitted by applicable law». — https://www.youtube.com/t/terms
- Там же «Reservation»: использование сервиса не даёт права на контент; «You are legally responsible for the Content you submit».
- 17 U.S.C. § 106 exclusive rights (репроизведение/распространение) — https://www.law.cornell.edu/uscode/text/17/106 ; добросовестное использование как исключение — § 107 — https://www.law.cornell.edu/uscode/text/17/107
- DMCA-inducement (ответственность за «наведение» infringement) — MGM v. Grokster, 545 U.S. 913 (2005) — https://www.law.cornell.edu/supremecourt/text/545/913

Оценка: сам локальный архив пользователя — это личная копия, риск на пользователе (так и написано в ACCEPTABLE_USE/README). Но проект, который **вшивает yt-dlp и автоматически ставит скачанное в очередь**, потенциально попадает под inducement-анализ (Grokster: «цель — распространение, инструмент для этого»). Ключевые смягчающие факторы: AUP + датированные согласия + предупреждение при первой передаче + «скачивайте только то, на что у вас права». **Mesh/relay поднимает риск до «высокий+»**, потому что передача копии другому лицу = распространение (см. 1.6).

### 1.2 ToS площадок (YouTube и др.) — **высокий**

- YouTube ToS п.3: «access the Service using any automated means (such as robots, botnets or **scrapers**)» запрещено кроме public search engines / письменного разрешения / «permitted by applicable law». Скрейп метаданных и качалка через yt-dlp — это automated access без письменного разрешения. — https://www.youtube.com/t/terms
- YouTube ToS п.2: запрещено «circumvent, disable … or otherwise interfere with the Service … including features that (a) prevent or restrict the copying or other use of Content; or (b) limit the use of the Service or Content». Здесь риск: имитация TLS-отпечатка (curl_cffi) и replay кук «подтвердите, что вы не бот» могут быть прочитаны как «interfere with features that limit the use of the Service». Это **не** обход DRM/шифрования, но формулировка п.2 широкая. — https://www.youtube.com/t/terms
- YouTube API Services ToS §15 «Usage and Quotas»: «You … will not, and will not attempt to, exceed or circumvent use or quota restrictions» — https://developers.google.com/youtube/terms/api-services-terms-of-service
- YouTube API Services ToS §3.1: доступ к API Services разрешён только «to develop and operate your API Client(s) by the means described in the Agreement»; Developer Policies запрещают скрейп страниц YouTube как замену/дополнение API (Developer Policies, раздел II «Accessing YouTube Data», и путеводитель по compliance) — https://developers.google.com/youtube/terms/developer-policies и https://developers.google.com/youtube/terms/developer-policies-guide

Оценка: **высокий**, потому что именно «откат на скрейп при исчерпанной квоте» (app/data_api.py:9-15, 233) читается как circumvent quota + scrape-as-API-substitute. Это юридически худший фрагмент кода проекта. Смягчение: квотный отказ пишется честно, RSS-ленты — основной путь (RSS публичен и не является API-путём), OAuth — только youtube.readonly.

### 1.3 Лицензы зависимостей и packaging exe — **средний**

- PyInstaller исключение прямо разрешает распространять собранный exe под любой лицензией, «as long as it complies with the licenses of your dependencies», и не требует класть лицензию PyInstaller в приложение — https://pyinstaller.org/en/latest/license.html
- UPX: «either under the pure GPLv2+, or (at your option) under the GPLv2+ with special exceptions … granting the free usage for all binaries including commercial programs» — https://upx.github.io/
- PolyForm Noncommercial «Notices»: получатель любой части софта должен получить текст лицензии (или URL) и строки `Required Notice:` — https://polyformproject.org/licenses/noncommercial/1.0.0 и https://spdx.org/licenses/PolyForm-Noncommercial-1.0.0.html

Оценка: **средний** — сама архитектура вшитых зависимостей корректна (см. таблицу раздела 2). Разрыв «LICENSE/NOTICES не поставляются вместе с exe» закрыт: релизный пакет кладёт тексты условий и тексты лицензий бандла рядом с exe (`tools/build_legal_pack.py`, §5.2). Неточность была в этом review и в обратную сторону: cffi распространяется под `MIT-0` (MIT No Attribution) — так написано в тексте лицензии самого пакета и в его license expression, правка «MIT-0 → MIT» была ошибкой и возвращена.

### 1.4 Персональные данные / куки / OAuth — **средний**

- Локальное приложение без сервера: GDPR применим к «controller» , который определяет цели и средства обработки (ст. 4(7), ст. 3(1)) — https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CEX:32016R0495 ; исключение для чисто личной/домашней деятельности (ст. 3(2)) — тот же текст regulation.
- YouTube ToS: возраст 13+, для <18 нужно разрешение родителя («Who may use the Service?») — https://www.youtube.com/t/terms
- YouTube API Services ToS §7 «User Privacy and API Clients»: каждый API Client обязан иметь опубликованный privacy policy; §9.2 для пользователей из ЕС — EU User Consent Policy — https://developers.google.com/youtube/terms/api-services-terms-of-service
- Куки аккаунта: `app/google_auth.py` — DPAPI (CryptProtectData, user scope), копии в `accounts/<id>.bin`, значения не попадают в settings/журнал; временный Netscape cookies.txt в tempfile; OAuth `app/oauth.py` — PKCE S256 + loopback 127.0.0.1 ephemeral port, refresh-токен тем же DPAPI.

Оценка: **средний**. Для личного использования человек сам становится controller'ом (не проект) — GDPR на проект не ложится, но проект обязан не подталкивать к обратному. Реальные точки: DHT-анонс (IP + ключи поиска видимы всем слушателям публичной сети — README честно говорит об этом), журнал relay (отпечатки запросчиков), и требование API ToS §7 (опубликованный privacy policy для того, кто распространяет API-клиент).

### 1.5 Взрослый контент и возрастные гейты — **высокий** (и требует усиления текстов, не ослабления гейтов)

- Гейты в коде: `app/legal.py` (`adult_ok` — датированный факт, `aup_accepted_at`, `first_send_accepted`); `app/platforms.py` (`adult: True`, `adult_ids()` — скрытие из общих вкладок); вкладка скрыта до подтверждения 18+ (docs/PLAN-15H.md, M-этапы).
- 18 U.S.C. § 2257 (записи для «produced» материалов с actual sexually explicit conduct; «distributor» в определении § 2257(6)) — https://www.law.cornell.edu/uscode/text/18/2257
- 18 U.S.C. § 2257A и § 2257F для «simulated» — https://www.law.cornell.edu/uscode/text/18/2257A
- CSAM: абсолютно запретный контент, никакой юрисдикции «личной копии» — 18 U.S.C. § 2256 — https://www.law.cornell.edu/uscode/text/18/2256 ; AUP уже прямо запрещает его (docs/ACCEPTABLE_USE.md, п.5).

Оценка: **высокий**. Причина не в самом гейте (он датированный и корректный), а в публичных текстах: имя взрослой площадки и её домены сейчас живут в `ui_src/app.js` (в т.ч. mock-данные, собранные в `preview.html`) и в `app/platforms.py`. Публичный репозиторий/сборка, называющая взрослую площадку, даёт риск (a) trademark, (b) «этот проект — клиент порно-площадки», (c) усложняет защиту в copyright/inducement-споре (инструмент, «цель которого» — adult distribution, хуже защищается под Grokster). docs/REVIEW-WAVE1.md уже зафиксировал этот контракт — его надо довести до конца.

### 1.6 Mesh-обмен между машинами участников — **высокий**

Что реально передаётся между пирами (по коду и docs/mesh-platform.md):
- Подписанные манифесты Ed25519 `{remote_id, sha256, size, synced_at, ts, pubkey, sig}` (app/mesh/manifest.py) — «у меня файл с хешом H».
- TOFU-пины адресов и truststore (verified_via: tofu/manual/sas), жёсткий барьер отзыва; SAS 12 слов (app/mesh/sas.py, sas_words.py).
- Репутация ключей (offenses) и стоп-лист по хешу — решение человека (app/mesh/feedback.py, verify.py).
- Канал всегда TLS; эфемерный самоподписанный сертификат + аттестация SPKI ключом участника до первого байта (README, «Канал шифруется всегда»); чанки дополнительно шифруются под ключ получателя (app/mesh/crypt.py) — посредник не читает байты.
- Свой DHT-стек (BEP5/BEP42) через публичные bootstrap-роутеры BitTorrent; UPnP-проброс собственного роутера (app/mesh/nat.py); LAN-multicast hello; опциональный magic-wormhole в изолированный venv.
- Relay: opt-in на стороне ретранслятора, квоты `relay_daily_mb/files`, право отклонить, журнал запросов (docs/mesh-platform.md §7).

Юридически важно: это **не серверная дистрибуция контента** — серверов проекта нет; узел отдаёт только свои файлы с известным хешом по запросу подтверждённого участника; оператор relay отвечает за то, что пересылает сам. DMCA safe harbor (§512) тут неприменим и не нужен — см. раздел 1.1 источников в разделе 7. Оценка: **высокий** для участника-оператора (он распространяет), но структура opt-in/квот/отклонения/предупреждения «передаёте файл другому лицу» снижает риск проекта до **средний**, при условии что предупреждение и `first_send_accepted` не ослаблены.

### 1.7 «Устойчивость к отказам площадки» (bypass.py) — **высокий** (по восприятию, средний по механике)

Механика (app/bypass.py, docstring 1-42): конечный список дорог при фактическом отказе площадки — куки аккаунта, имитация TLS-отпечатка, зеркало домена из реестра, селектор формата/HLS, селектор качества, PO-токен/visitor-cookie подтверждения человека. **Обход DPI отсутствует**: никаких прокси, winws/zapret, правок маршрутизации; в журнале площадки называются нейтрально. README и LEGAL_FAQ прямо пишут: «не поставляет и не конфигурирует средства обхода блокировок».

Оценка: механически это «повторный запрос другим способом» (средний риск), но **ToS п.2** («circumvent, disable … or otherwise interfere … features that limit the use of the Service») делает это **высоким по восприятию**, особенно дорогу «bot-подтверждение → токен/куки»: площадка просит подтверждение человека, а программа подставляет cookie-факт подтверждения. Это надо формулировать нейтрально и честно («площадка просит подтверждение — программа показывает, что происходит; решение и аккаунт — ваши»), а не как «преодоление ограничений».

### 1.8 Trademark / брендинг — **высокий**

- YouTube API Services ToS §13 «Publicity»: «You must not make any public statements … that suggests partnership with, or sponsorship or endorsement by, YouTube without YouTube's prior review and written approval» — https://developers.google.com/youtube/terms/api-services-terms-of-service ; §10 Brand Features and Attribution; §11 Proprietary Rights Notices (не удалять/менять notices и ссылки на terms) — тот же документ.
- YouTube Branding Guidelines для API clients — https://developers.google.com/youtube/terms/branding-guidelines
- UPX «All trademarks, brands, and names are the property of their respective owners» — https://upx.github.io/
- Текущее состояние проекта: README содержит «не аффилирован, не одобрен и не спонсируется YouTube и Google» (хорошо). Имя и домены взрослой площадки в публичных текстах и в собранных артефактах **не** используются: `ui_src/app.js` называет вкладку нейтрально («Взрослая площадка», `ADULT_LABEL_RU`), mock-данные идут с placeholder-адресом `adult-site.invalid`, собранный `preview.html` сверяется со стражем `tests/test_public_texts.py` (имя и домены + актуальность сборки). Внутренние id и домены реестра (`app/platforms.py`, `"label": "PornHub"`) остаются и не являются публичным текстом: для взрослой площадки окно подставляет нейтральную подпись, а реестровая label нужна классификатору ссылок и списку источников. Внутренние id/домены для классификации ссылок допустимы, **имя в пользовательском и публичном тексте — нет** (контракт из docs/REVIEW-WAVE1.md, п.4 — закрыт).

Оценка: **высокий** по природе риска (trademark + «проект = клиент порно-площадки»), но правка выполнена: публичные тексты и артефакты нейтральны, сверка автоматическая — `tests/test_public_texts.py` для окна/превью и `tools/build_legal_pack.py --check` для текстов релизного пакета.

### 3.6 Mesh: обмен между машинами участника

> **Что такое mesh.** Это обмен между машинами самих участников — не
> серверная дистрибуция контента. Серверов проекта нет: узел участника
> принимает соединения на своём порту, отдаёт только свои файлы с известным
> sha256 и только по запросу участника, и получает файлы с проверенным хешем.
> Метаданные всегда ваши, от площадки; чужие названия и даты не принимаются.
>
> **Доверие — личное.** Личность участника решает сверка отпечатка (лично
> или по 12 словам SAS), не ник и не адрес. Первый контакт запоминается
> (TOFU), дальше несовпадение ключа = отказ. Отзыв устройства — жёсткий
> барьер: манифесты и файлы отозванного ключа отсекаются, включая будущие.
> Манифесты подписаны ключом участника (Ed25519), канал шифруется TLS,
> аттестация ключа проверяется до первого байта запроса; чанки файла
> дополнительно шифруются под ключом получателя — посредник не может
> прочитать пересылаемые байты.
>
> **Что видно окружающим.** Объявления в публичной DHT-сети видны всем, кто
> эту сеть слушает: ваш адрес и под какими ключами (id видео, ник) вы
> объявляетесь. Список id, которые вы запрашиваете, наблюдателю не виден —
> запросы идут по зашифрованному каналу. Метаданных и списка ваших файлов в
> объявлениях нет.
>
> **Ответственность участника.** Вы отвечаете за то, что отдаёте со своей
> машины, и — если включили relay — за то, что пересылает ваш узел. Квоты,
> право отклонить запрос и журнал запросов существуют для этого. Ретранслируется

> просьбе сверх вашего. Программа не даёт «общую библиотеку»: доступ
> строгий, без манифеста ничего не отдаётся.
>
> **Внешний адрес.** Проброс порта делает ваш собственный роутер по UPnP;
> сторонним сервисам ничего не уходит. Роутер без UPnP или отказ — не
> ошибка: остаётся работа по вашей сети (LAN), причина пишется в журнал.

## 4. Что нельзя формулировать: запретные формулировки и нейтральные альтернативы

Левая колонка — формулировки, которые в публичных текстах (README, AUP, FAQ,
подсказки UI, описания релиза, заметки о площадке) ставить нельзя. Правая —
что писать вместо них.

| Нельзя формулировать | Почему | Нейтральная альтернатива |
|---|---|---|
| «скачивает любой контент» / «качает всё подряд» | описывает инструмент как средство mass-download → усиливает inducement-анализ (Grokster) и противоречит AUP | «помогает вести **ваш** личный архив того, на что у вас есть права; решение о содержимом — за вами» |
| «официальный клиент площадки» / «клиент YouTube» | YouTube API Services ToS §13 запрещает публичные statements о partnership/sponsorship/endorsement без письменного разрешения; §10-§11 о Brand Features | «сторонний инструмент, не аффилирован, не одобрен и не спонсируется YouTube и Google» |
| «обходит ограничения площадки» / «преодолевает блокировки и запреты» | YouTube ToS п.2 («circumvent, disable … or otherwise interfere … features that … limit the use of the Service») и API ToS §15 («не превышать и не обходить квоты») | «работает при отказе площадки: повторные дороги того же запроса — ваши куки, зеркало домена, другой вариант формата/качества; ограничения площадки остаются ограничениями» |
| «обход блокировок», «обход DPI», «анти-DPI», «zapret-обход», «anti-censorship» | любой публичный текст об обходе цензуры/фильтров читается как circumvention и как «поставляет средства обхода» | «совместимость с вашими сетевыми инструментами: программа работает рядом с уже имеющимися у вас DPI/VPN-средствами и не управляет ими» |

| «снимает DRM» / «расшифровывает streams» | прямой circumvention-claim | «берёт потоки так, как их отдаёт площадка; склейка — после установки ffmpeg пользователем» |

| «программа не несёт ответственности за незаконные действия» | формулировка выглядит как «инструмент допускает незаконное» — прямо ухудшает позицию автора (и inducement, и AUP) | «программа — инструмент; ответственность за содержимое и за ваши действия — на человеке; правила использования (AUP) это фиксируют, лимиты и opt-in встроены» |
| «авто removes чужие запреты» / «mesh обходит приватные видео» / «восстановление любых удалённых видео» | превращает mesh в обход чужих доступов; противоречит AUP п.2 | «mesh годится для восстановления **вашего** ранее скачанного файла с сохранёнными правами; чужие запреты остаются чужими; отдаются только свои файлы с известным хешом» |
| «неограниченная квота / безлимитный API» / «качаем метаданные мимо API» | API ToS §15 (не обходить квоты), Developer Policies III.E.6 (scraping запрещён) | «официальный путь — Data API; когда ключ/вход не настроены, квота исчерпана или API отказал, метаданные берутся из публичных лент канала (RSS); отказ пишется честно» |
| «программа проверяет возраст» / «верифицирует 18+» | возрастная verification не выполняется программой; формулировка = ложное утверждение (Developer Policies II.2) и путает с 2257-обязанностями | «вкладка скрыта до вашего явного подтверждения; программа запоминает факт подтверждения с датой, возраст не проверяет и не подтверждает от имени площадки» |
| «встроенный VPN/прокси» / «мы пробрасываем порты наружу» | falsely описывает сеть и добавляет «distribution of circumvention tools» | «проброс делает ваш собственный роутер по UPnP; наружу объявляется только ваш адрес под вашим ключом; VPN/прокси — ваши инструменты, мы их не поставляем» |
| «вшита криптография собственного изобретения» | misleading + усложняет экспортные/юрисдикционные вопросы | «общедоступные открытые алгоритмы (TLS 1.3, Ed25519, X25519, HKDF-SHA256, ChaCha20-Poly1305) из стандартной open-source криптографии; код открыт» |
| «название adult-площадки и её домены в публичном тексте/UI/mock» | trademark + «проект = клиент порно-площадки» (ухудшает copyright-защиту) | «взрослая площадка» / placeholder-URL в mock; внутренние id и домены классификатора остаются; пересобрать preview.html |

**Сквозное правило.** Любой текст о площадке: нейтральное слово «площадка»,
имя только там, где оно необходимо как имя сервиса (внутренний реестр,
классификатор ссылок), никогда — в подсказках, mock-данных, описаниях релиза и
в собранных артефактах. Любой текст о сети: «совместимость», а не «обход».
